# Qwen ASR Python

As of: 2026-11-26 15:31:22 UTC (+0000)
Codebase commit: `d1402a0841aed43642870ef22ad67674dde7ef0e`

TEN ASR extension for Qwen `qwen-audio-3.1-asr-flash-streaming` over the
DashScope duplex WebSocket API.

Use `${env:DASHSCOPE_API_KEY}` in `property.json`; do not put an API key in the
extension package. The default request uses 16 kHz PCM, `near_meeting_16k`, and
240 ms sentence silence, matching the Qwen admission report.

Startup completes after the WebSocket and recognition task are ready.
Buffered audio is sent by a separate task so a slow send cannot hold startup
open. Live audio stays behind the buffered frames. Stop and connection
replacement cancel the buffer task before closing the client; replacement
retains unfinished frames for the next connection.

Recognition results include request details in `metadata.asr_info`:

| Field | Source |
| --- | --- |
| `request_id` | `payload.output.request_id`, with a fallback to `payload.request_id` |
| `task_id` | Task ID generated by this client and echoed by the server |
| `task_uuid` | Supplier task ID returned in the event header |
| `connection_request_id` | `x-request-id` from the WebSocket handshake response |

Task lifecycle and error logs include the available request details. Error
reports retain them after client cleanup. Starting another task clears its
previous request ID and supplier task ID; the connection request ID remains
valid for the same WebSocket. Optional IDs are omitted when unavailable;
`request_id` remains null when no result request ID is known.

Finalize ends the current recognition task without resetting the base audio
timeline or cumulative send metrics. Each successfully started task records its
origin in the cumulative provider-audio timeline; sentence and word timestamps
are mapped through that origin. The same accounting is retained across reconnects.

Set `params.language` to the fallback language for ASR results, for example
`en-US`. Initialization merges known config fields from `params` using
`config.update(config.params)` before applying defaults and validating config.
`params.language` takes precedence over the top-level `language` property; the
top-level property remains supported when the nested value is absent.
Explicit `params.language_hints` take precedence over
hints derived from this language. Vendor-reported result languages take
precedence over the configured fallback.
